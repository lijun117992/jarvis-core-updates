## 已确认需求与实现

- 原创可爱蓝色小狐妖男孩；待机、偷听、思考、工作、着急、哭泣、快乐、无语，共 64 帧，可扩展。
- 单击听写、双击悬浮输入，不能恢复 dialogs.rawInput 白框。偷听托住、放大并抖动朝屏幕中间的耳朵：原图朝画面左探耳，角色在屏幕左侧时镜像。
- 靠边约 4.5 秒半藏，第一次点击只展开；触摸窗口保留在屏内。输入/回复不透明浅色深字；回复可展开、滚动、复制、收起找回。
- 普通回答默认自动朗读，尊重媒体音量，不主动调高；通知仍保留耳机/响铃判断。开关可关闭并保存。
- 系统/Fish/自动自由切换，默认系统。系统速度/音高 0.5～2.0；本段音色参数固定，修改作用于下一次回答。
- 普通回答整段合成，超过 2200 UTF-16 单元才分大块。无固定 Fish ID 的超长回答改用系统。Fish 多候选名称/ID 保存、选择、重启沿用，相同 ID 改名去重，不自动切换播放来源。
- 用户已澄清逐句换声发生在旧版，不可当成 preview4/5/6 的实际效果证据。

## 声音边界

Fish 使用 `model: s2.1-pro-free` 请求头、latency normal，prosody.speed 0.8～1.3，情绪轻微变速。情绪/重音用英文方括号，只放专用语音文本；气泡与系统 TTS 保留干净正文。模型对标签的响应需试听。没有固定参考 ID 时，不保证不同回答是同一说话人。

系统测试与实际共用实例和配置函数；跟随系统所选音色，不通过 setLanguage() 重置。用户系统页提供温柔女声、清冷女声、明朗男声，当前选择明朗男声；厂商 getVoices() 未必公开这些内部选项，不能伪造名单或断言系统没有音色。更改系统设置后可刷新引擎。

系统有范围回调则按回调推进文字，否则估算/结束校正；Fish 按实际音频位置和时长估算。不是精确字时间戳或口型同步。未实现 DeepSeek SSE、持久音频流；整段 Fish 有合成等待。

## 当前关键故障

用户明确反馈系统直接识别在桌面和前台均为 ERROR_CLIENT(5)，组件名未公开。不能只归因后台限制或缺麦克风权限；TTS、输入法语音和 SpeechRecognizer 是不同通路。

preview6 新增设备端服务优先，以及显式选择的系统语音 Activity；兼容测试结果不发模型。下一步让用户先测“系统语音页面”，成功才切换该方式。它会显示系统原生收音界面，取决于手机提供入口。**兼容路径没有真机结果，不能承诺已解决 5。** 未接云 ASR，不得静默增加付费识别或上传录音。

AutoJs6 音量加停止脚本是宿主设置，用户需自行关闭，脚本不能保证阻止宿主停止。初次 floaty 需工作线程等待创建完成后在主线程绑定；通知勾选不应决定能否召唤。旧截图曾暴露这类问题，不能冒充新版已全面通过。
